# Monitoring Azure Container Apps

Monitoring Azure Container Apps helps you understand whether an application is healthy, how much traffic it receives, how many replicas are running, and why a container or revision failed.

Azure Container Apps integrates with Azure Monitor and provides:

- Near-real-time log streaming
- Console, system, and HTTP logs
- Azure Monitor metrics
- Log Analytics queries
- Azure Monitor alerts
- Application Insights when the application is instrumented with an Application Insights SDK

The examples below use the variables defined in `deploy_aca.md`:

```powershell
$resourceGroup = "AI-200"
$containerAppName = "oreilly-aca-ai200-cc"
```

## Check the application and revision status

View the container app:

```powershell
az containerapp show `
  --name $containerAppName `
  --resource-group $resourceGroup `
  --output table
```

List its revisions:

```powershell
az containerapp revision list `
  --name $containerAppName `
  --resource-group $resourceGroup `
  --output table
```

This shows whether a revision is active and whether it was provisioned successfully.

## Log types

Azure Container Apps provides three main log types:

| Log type | Contents |
| --- | --- |
| Console logs | Output written by the container to `stdout` and `stderr`, including application errors |
| System logs | Events generated by Azure Container Apps, including image-pull, revision, scaling, and container-start events |
| HTTP logs | Request information emitted by the ingress layer when HTTP logging is enabled through diagnostic settings |

## Stream console logs

Use console logs to investigate exceptions and other messages generated by the application:

```powershell
az containerapp logs show `
  --name $containerAppName `
  --resource-group $resourceGroup `
  --type console `
  --follow
```

Press `Ctrl+C` to stop following the logs.

Display only recent console messages:

```powershell
az containerapp logs show `
  --name $containerAppName `
  --resource-group $resourceGroup `
  --type console `
  --tail 100
```

## Stream system logs

Use system logs to investigate platform events such as revision provisioning, container crashes, and image-pull failures:

```powershell
az containerapp logs show `
  --name $containerAppName `
  --resource-group $resourceGroup `
  --type system `
  --follow
```

## View logs in Log Analytics

When the Container Apps environment uses Log Analytics, logs from its container apps are stored in common tables.

Query application console logs:

```kusto
ContainerAppConsoleLogs_CL
| where ContainerAppName_s == "oreilly-aca-ai200-cc"
| project TimeGenerated, RevisionName_s, ContainerName_s, Log_s
| order by TimeGenerated desc
```

Query Container Apps system logs:

```kusto
ContainerAppSystemLogs_CL
| where ContainerAppName_s == "oreilly-aca-ai200-cc"
| project TimeGenerated, RevisionName_s, Log_s
| order by TimeGenerated desc
```

In the Azure portal, open the container app and select **Monitoring > Logs** to run these queries.

Log Analytics records can take several minutes to appear. Use log streaming when immediate output is required.

## View metrics

Azure Monitor metrics show numeric measurements such as requests, replicas, CPU usage, memory usage, response time, and restarts.

In the Azure portal:

1. Open the container app.
2. Select **Monitoring > Metrics**.
3. Select a metric and aggregation.
4. Filter or split the chart by revision or replica when those dimensions are available.

List the metrics available for the container app with Azure CLI:

```powershell
$containerAppId = az containerapp show `
  --name $containerAppName `
  --resource-group $resourceGroup `
  --query id `
  --output tsv

az monitor metrics list-definitions `
  --resource $containerAppId `
  --output table
```

## Configure alerts

Azure Monitor alerts can notify users or trigger an action when a metric or log condition is met. Examples include:

- A revision fails to provision
- The application returns too many server errors
- CPU or memory usage remains high
- A container restarts repeatedly
- No replicas are available

In the Azure portal, open the container app and select **Monitoring > Alerts > Create > Alert rule**. Choose a metric or log query, define its threshold, and attach an action group.

## Application Insights

Application Insights can collect application-level telemetry such as requests, dependencies, exceptions, and distributed traces. Azure Container Apps does not automatically add the Application Insights agent, so the application must be instrumented with an Application Insights SDK or OpenTelemetry.
