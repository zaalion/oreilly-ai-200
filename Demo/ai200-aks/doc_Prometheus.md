# Managed Prometheus for AKS

Enable **Managed Prometheus** to monitor:

- Node, pod, and container CPU and memory usage
- Pod availability and deployment state
- Application metrics exposed through `/metrics`
- PromQL queries
- Grafana dashboards
- Alerts for resource pressure or unhealthy workloads
- Historical metrics without managing your own Prometheus servers

Azure operates the Prometheus backend and handles scaling and upgrades. Metrics are retained for up to 18 months, and the service integrates directly with Azure Monitor and Grafana.

Pricing is based primarily on metric ingestion and queries.

Managed Prometheus collects **metrics**. Container Insights and Log Analytics collect **container logs**. Avoid sending the same Prometheus metrics to both Managed Prometheus and a Log Analytics workspace because redundant collection can increase costs.

## Managed Prometheus compared with ACNS

Managed Prometheus and Advanced Container Networking Services (ACNS) Network Observability are complementary rather than alternatives.

| Feature | Managed Prometheus | ACNS Network Observability |
| --- | --- | --- |
| Purpose | General cluster and application metrics platform | Detailed Kubernetes network visibility |
| Shows | CPU, memory, pod state, deployment health, and custom application metrics | Pod-to-pod traffic, DNS latency and failures, packet drops, TCP resets, ports, protocols, and network-policy decisions |
| Data | Time-series metrics queried with PromQL | Network metrics plus optional flow logs |
| Visualization | Azure Monitor and Grafana | Prometheus and Grafana for metrics; Log Analytics or Hubble for network flows |
| Pricing | Metric ingestion and queries | ACNS charge per node per hour, plus applicable Prometheus and Log Analytics ingestion |

ACNS uses eBPF and Cilium to produce detailed network telemetry. Managed Prometheus can collect the network metrics generated by ACNS.

Persistent flow logs require a `ContainerNetworkLog` custom resource. Enabling ACNS makes the capability available, but it does not begin generating stored flow logs until this custom resource defines the traffic to capture.
