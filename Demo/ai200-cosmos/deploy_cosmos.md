# Deploy a Serverless Azure Cosmos DB Vector Store

This guide creates a serverless Azure Cosmos DB for NoSQL account, a database, and a container configured for vector search.

## Scenario: semantic course search

The database stores a small catalog of training courses. A user can search by meaning instead of requiring exact keywords.

For example, the query:

```text
How can I protect access to cloud applications?
```

can retrieve a course titled **Microsoft Entra ID and managed identities**, even though the query does not contain the course title.

Each course document stores:

- Course ID
- Category
- Title
- Description
- A vector embedding generated from the title and description

```text
Cosmos DB account: serverless
└── Database: CourseCatalog
    └── Container: courses
        ├── Partition key: /category
        └── Vector path: /descriptionVector
```

## How semantic retrieval works

1. An embedding model converts each course description into a numeric vector.
2. The course and its vector are stored together in Cosmos DB.
3. The same embedding model converts the user's search text into a vector.
4. `VectorDistance()` compares the search vector with the stored vectors.
5. Cosmos DB returns the courses whose meaning is most similar to the search text.

The stored content and the search text must use the same embedding model and embedding dimensions.

```powershell

$resourceGroup = "AI-200"

$containerName = "courses"
```

Azure Cosmos DB account names are globally unique. The random suffix helps produce an available name.

## 3. Create a serverless Cosmos DB account with vector search

Create an Azure Cosmos DB for NoSQL account with the serverless and vector-search capabilities enabled:

```powershell
az cosmosdb create `
  --name $accountName `
  --resource-group $resourceGroup `
  --locations regionName=$location failoverPriority=0 isZoneRedundant=False `
  --default-consistency-level Session `
  --capabilities EnableServerless EnableNoSQLVectorSearch
```

Verify the account and its capabilities:

```powershell
az cosmosdb show `
  --name $accountName `
  --resource-group $resourceGroup `
  --query "{name:name, endpoint:documentEndpoint, capabilities:capabilities[].name}" `
  --output json
```

The capabilities should include `EnableServerless` and `EnableNoSQLVectorSearch`. Vector-search enablement can take several minutes to finish.

Serverless accounts charge for the request units consumed by database operations. Do not specify database or container throughput when creating the resources below.

## 4. Create the database

```powershell
az cosmosdb sql database create `
  --account-name $accountName `
  --resource-group $resourceGroup `
  --name $databaseName
```

## 5. Define the vector embedding policy

Create a file named `vector-policy.json`:

```json
{
  "vectorEmbeddings": [
    {
      "path": "/descriptionVector",
      "dataType": "float32",
      "dimensions": 1536,
      "distanceFunction": "cosine"
    }
  ]
}
```

The policy specifies:

- `/descriptionVector` as the document property containing the vector
- `float32` as the vector data type
- `1536` dimensions, matching the default output of `text-embedding-3-small`
- Cosine similarity for comparing text embeddings

If the embedding deployment produces a different number of dimensions, change `dimensions` before creating the container.

## 6. Define the indexing policy

Create a file named `indexing-policy.json`:

```json
{
  "indexingMode": "consistent",
  "automatic": true,
  "includedPaths": [
    {
      "path": "/*"
    }
  ],
  "excludedPaths": [
    {
      "path": "/\"_etag\"/?"
    },
    {
      "path": "/descriptionVector/*"
    }
  ],
  "vectorIndexes": [
    {
      "path": "/descriptionVector",
      "type": "quantizedFlat"
    }
  ]
}
```

The embedding array is excluded from the normal Cosmos DB index because the vector index handles that property.

`quantizedFlat` supports the 1,536 dimensions generated by `text-embedding-3-small`. When fewer than 1,000 vectors are stored, Cosmos DB performs a full vector scan instead of using the quantized index. This is sufficient for the small classroom dataset; the configured index becomes useful as the dataset grows.

Vector policies and vector indexes should be chosen before the container is created. Changing them later can require creating a new container.

## 7. Create the vector-enabled container

Run this command from the directory containing the two policy files:

```powershell
az cosmosdb sql container create `
  --account-name $accountName `
  --resource-group $resourceGroup `
  --database-name $databaseName `
  --name $containerName `
  --partition-key-path "/category" `
  --idx '@indexing-policy.json' `
  --vector-embeddings '@vector-policy.json'
```

The `/category` partition key groups related courses, such as `AI`, `Security`, and `Data`.

Verify the container:

```powershell
az cosmosdb sql container show `
  --account-name $accountName `
  --resource-group $resourceGroup `
  --database-name $databaseName `
  --name $containerName `
  --output json
```

## 11. Add sample courses and run semantic search

Create a file named `vector_search.py`:

```python
import os

from azure.cosmos import CosmosClient
from azure.identity import DefaultAzureCredential, get_bearer_token_provider
from openai import OpenAI


cosmos = CosmosClient.from_connection_string(
    os.environ["COSMOS_CONNECTION_STRING"]
)
container = (
    cosmos.get_database_client(os.environ["COSMOS_DATABASE_NAME"])
    .get_container_client(os.environ["COSMOS_CONTAINER_NAME"])
)

token_provider = get_bearer_token_provider(
    DefaultAzureCredential(),
    "https://ai.azure.com/.default",
)
openai = OpenAI(
    base_url=os.environ["OPENAI_ENDPOINT"],
    api_key=token_provider,
)
embedding_deployment = os.environ["EMBEDDING_DEPLOYMENT"]

courses = [
    {
        "id": "course-001",
        "category": "Security",
        "title": "Microsoft Entra ID and managed identities",
        "description": (
            "Protect cloud applications with identity-based authentication, "
            "managed identities, and role-based access control."
        ),
    },
    {
        "id": "course-002",
        "category": "AI",
        "title": "Build generative AI applications",
        "description": (
            "Create applications that send prompts to language models and "
            "generate natural-language responses."
        ),
    },
    {
        "id": "course-003",
        "category": "Data",
        "title": "Store JSON data with Azure Cosmos DB",
        "description": (
            "Build globally distributed applications with a NoSQL database, "
            "partitioned containers, and low-latency queries."
        ),
    },
    {
        "id": "course-004",
        "category": "AI",
        "title": "Vector search and semantic retrieval",
        "description": (
            "Convert text into embeddings and retrieve documents according "
            "to meaning instead of exact keyword matches."
        ),
    },
]

# Embed and store the sample courses.
texts = [f"{course['title']}. {course['description']}" for course in courses]
embedding_response = openai.embeddings.create(
    model=embedding_deployment,
    input=texts,
)

for course, embedding_item in zip(courses, embedding_response.data):
    course["descriptionVector"] = embedding_item.embedding
    container.upsert_item(course)

print(f"Stored {len(courses)} courses.")

# Convert the user's natural-language search into a vector.
search_text = "How can I protect access to cloud applications?"
search_vector = openai.embeddings.create(
    model=embedding_deployment,
    input=search_text,
).data[0].embedding

query = """
SELECT TOP 3
    c.id,
    c.category,
    c.title,
    c.description,
    VectorDistance(c.descriptionVector, @embedding) AS similarityScore
FROM c
ORDER BY VectorDistance(c.descriptionVector, @embedding)
"""

results = container.query_items(
    query=query,
    parameters=[
        {"name": "@embedding", "value": search_vector}
    ],
    enable_cross_partition_query=True,
)

print(f'\nSearch: "{search_text}"')
for result in results:
    print(
        f"{result['title']} "
        f"(category: {result['category']}, "
        f"score: {result['similarityScore']:.4f})"
    )
```

Run the sample:

```powershell
python .\vector_search.py
```

The identity signed in through Azure CLI is used to call the embedding model. It must have the `Cognitive Services OpenAI User` role on `oreilly-foundry-ai200`.

The expected first result is **Microsoft Entra ID and managed identities** because its description is semantically related to protecting application access.

## 14. Choose how to use the vector database

The Cosmos DB vector store can be called by different types of applications:

- **Your own application:** A web app, API, console app, or background service can generate an embedding and query Cosmos DB directly.
- **An AI agent:** An agent can call a tool or API that searches Cosmos DB and returns relevant records.
- **A RAG application:** The application searches Cosmos DB for relevant content, adds that content to the model prompt, and asks the model to generate an answer.

A typical retrieval-augmented generation flow is:

```text
User question
    ↓
Application or agent
    ↓
Embedding model converts the question to a vector
    ↓
Cosmos DB vector search finds relevant records
    ↓
Relevant records are sent to the language model
    ↓
The generated answer is returned to the user
```

Cosmos DB performs the storage and semantic retrieval. The application or agent decides when to search the database and how to use the retrieved records.

## Troubleshooting

- **The account name is unavailable:** Generate a new suffix and run the account creation command again.
- **Vector policy is rejected:** Confirm that `EnableNoSQLVectorSearch` is present and wait for feature enablement to complete.
- **Embedding dimensions do not match:** Confirm the model's output length and make it equal to the container policy's `dimensions` value.
- **Foundry returns an authorization error:** Confirm that the signed-in identity has the `Cognitive Services OpenAI User` role.
- **The query returns an error:** Confirm that every stored vector contains exactly 1,536 numeric values and that the query uses `TOP`.
- **The vector index is not used for the sample:** `quantizedFlat` requires at least 1,000 vectors; a smaller classroom dataset uses a full scan.
